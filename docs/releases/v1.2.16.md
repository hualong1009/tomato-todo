# 🍅 番茄待办 v1.2.16 — 改完就同步，手机端也能看到同步状态

WebDAV 同步从「等定时器」变成「改完就走」：保存详情、勾选完成、改分组、拖排序……任何改动约 1.6 秒后自动同步，不用再手动点。同时手机端顶部栏加上了和桌面标题栏一样的同步状态，一眼就知道「同步到哪儿了」。

## ✨ 新特性

- **改动即同步（桌面端 + 手机端）**：本机一有数据改动就排队同步，1.6 秒内的连续编辑会合并成一次。已经有本机改动，所以直接上传，省掉「先读远端」的那一次请求。
- **手机端同步状态**：顶部栏显示小药丸——`已同步 · 09:05` / `同步失败` / `等待同步`，点一下立即同步（同步中显示转圈 + 「同步中」），长按或悬浮看完整说明（含上次同步的完整时间与失败原因）。只在真正填了 WebDAV 地址并启用后出现，不影响没用同步的用户。
- **回到窗口就补一次**：桌面端窗口重新获得焦点、手机端切回前台时，距离上次同步超过设定间隔就立刻同步一次，切设备后不用干等定时器。

## 🛠 行为变化

- 设置里的「自动上传」改名为「**变动后自动同步**」——它现在管的是「改动后立刻同步」，和「定时双向同步」互相独立：
  - 关掉定时同步 → 本机改动照样立刻上传，只是不再定期去远端找别人的改动；
  - 关掉变动后同步 → 改动攒到下次定时同步（或手动同步）时一起上传。
- 定时同步失败仍然不弹提示（错误记在设置页「上次错误」）；手动 / 点击同步失败会提示原因。

## 🔧 实现细节

- 新增 `shouldSyncOnChange()`（`src/shared/webdavSync.ts`）：`enabled && url && autoUpload`，与 `shouldAutoSync()`（依赖定时间隔）分离。
- `AppStore.scheduleWebdavUpload()` 改为调用 `syncWebDAV({ dirty: true })`；`dirty` 时跳过远端 savedAt 探测，直接上传（首次没有同步基准时仍会先探测，避免新设备用空数据覆盖远端备份）。
- 同步进行中又来的请求走 `scheduleFollowUpSync()` 补跑一次，不受「变动后自动同步」开关影响。
- 主进程 `mainWindow.on('focus')` → `store.nudgeAutoSync()`：受定时间隔约束，不会每次切窗口都发请求。
- 新增 `src/shared/syncStatus.ts`（`syncStatusLabel` / `syncStatusDetail`），桌面标题栏与手机顶部栏共用同一套文案；`capacitorApi` 的 `scheduleWebDAVUpload` / `flushPendingWebDAVWork` 同样走 `dirty` 路径。

## 🧪 测试

- 单测 225 项通过（新增 9 项）：改动后自动同步、开关关闭后不上传、关掉定时仍同步、`dirty` 跳过探测、手机端「已同步过之后直接上传」、同步状态文案四种状态。
- e2e 手机端新增断言：未配置 WebDAV 时无状态药丸 → 配置后出现 → 保存即完成首次上传 → 新建待办自动同步 → 点击药丸立即同步。
- 桌面端 e2e（Electron 冒烟、便签窗口、下拉、安全、MCP stdio）全部通过。

## 🔄 升级说明

Android v1.2.10 起为固定正式签名，可直接覆盖安装，数据保留。若目前安装的是 v1.2.1～v1.2.9 的 GitHub APK（debug 签名），请先在旧版把数据备份到 WebDAV 并确认上传成功，再卸载旧版安装本版并恢复；卸载会清除本机数据。

WebDAV 是备份式同步，不合并两台设备的并发编辑：两端都改过时保留本机数据并覆盖远端。想拿到别的设备的改动，让它先上传、本机再同步（或等下次定时同步）。
