# 🍅 番茄待办 v1.2.10 — 修复安卓 APK 发布签名

**重要升级说明：请先阅读以下内容，再处理已安装的 Android 应用。** 本版修复了 GitHub Actions 发布 APK 时意外回退为每次不同的 debug 签名的问题。v1.2.10 起发布流水线要求使用仓库外的固定正式 keystore，并在上传前比对 APK 与 keystore 的证书 SHA-256；签名错误时流水线会失败，绝不发布 APK。

## 🐛 问题修复

- **Android 安装包签名稳定**：旧流水线把签名配置写在 `android/`，却让 Gradle 从上一层目录读取，最终静默使用了 CI runner 每次新生成的 debug 签名。现在使用绝对路径传递签名配置，缺失即停止构建。
- **发布前验签**：除校验 APK 有签名外，还对比 APK 证书与发布 keystore 的 SHA-256，防止再次误发 debug 签名包。
- v1.2.10 的正式签名证书 SHA-256：`7b06c868fa35be703fa540948edff2312c4072b0a33c355c299ff8781a592aeb`。

## ⚠️ Android 升级与数据保留

GitHub Releases 的 **v1.2.1～v1.2.9 APK** 曾使用不同的临时 debug 签名；Android 不允许用另一签名覆盖已安装应用。**无法通过再次下载或修改版本号绕过这一限制。**

1. **先在旧版中把待办和分组备份到 WebDAV，并确认上传成功、知道服务器地址/路径/加密密码。没有可恢复备份时不要卸载。**
2. 记下需要重新填写的本机设置（例如 AI 接口、WebDAV 账号）；WebDAV 备份只包含待办与分组，不包含密钥和本机设置。
3. 卸载旧版（这会清除本机应用数据），安装下方 v1.2.10 APK，再填写 WebDAV 设置并从远端恢复。

如果当前安装的是**同一正式 keystore 签名**的本地测试包或正式包，则可直接覆盖，不需要卸载。v1.2.10 及之后使用这一固定证书的正式包可以互相覆盖升级。
